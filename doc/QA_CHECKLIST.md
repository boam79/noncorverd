# 비급여 가격 비교 기능 QA 체크리스트

## 목적
실데이터 기반 비급여 가격 비교 기능이 정확하게 작동하는지 검증하기 위한 체크리스트입니다.

## 테스트 환경
- **날짜**: 2025-11-14
- **백엔드**: AWS EC2 (http://54.180.251.93:3000)
- **프론트엔드**: Vercel (배포 후 URL)
- **API 키**: 공공데이터포털 단일 키 사용

---

## 1. 기본 기능 검증

### 1.1 병원 선택 및 비교 페이지 이동
- [ ] 메인 페이지에서 병원 2개 이상 선택
- [ ] Floating Compare Bar에 선택된 병원 수 표시 확인
- [ ] "비교하기" 버튼 클릭 시 `/comparison` 페이지로 이동
- [ ] 비교 페이지에서 선택된 병원 목록 정확히 표시

### 1.2 가격 정보 로딩
- [ ] 비교 페이지 진입 시 로딩 스피너 표시
- [ ] 가격 정보 로딩 완료 후 비교 테이블 표시
- [ ] 로딩 시간이 3초 이내 (캐시 히트 시 즉시 표시)

### 1.3 에러 처리
- [ ] API 호출 실패 시 에러 메시지 표시
- [ ] "다시 시도" 버튼 클릭 시 재시도 동작 확인
- [ ] 일부 병원만 실패한 경우 부분 데이터 표시 확인

---

## 2. 비교 테이블 데이터 정확성 검증

### 2.1 항목 수 및 평균가
- [ ] 각 병원의 항목 수가 실제 API 응답과 일치하는지 확인
- [ ] 병원별 평균 가격이 정확히 계산되는지 확인
- [ ] 평균가 표시 형식: "평균: XXX,XXX원"

### 2.2 가격 데이터 정확성
**검증 방법**: 백엔드 `test-pricing-api.js`로 실제 API 응답과 비교

- [ ] 항목명이 실제 API의 `npayKorNm` 또는 `yadmNpayCdNm`과 일치
- [ ] 가격이 실제 API의 `curAmt`와 일치 (원 단위)
- [ ] 단위(`회/일/건`)가 항목명에서 올바르게 추출되었는지 확인

### 2.3 공통 항목 필터링
- [ ] "공통 항목" 모드 선택 시 모든 병원에 공통으로 있는 항목만 표시
- [ ] 공통 항목 수가 정확히 계산되는지 확인
- [ ] "전체 항목" 모드 선택 시 모든 항목 표시

### 2.4 가격 차이 계산
- [ ] 평균 대비 차이(`diff`)가 정확히 계산되는지 확인
- [ ] 퍼센트 차이(`percentDiff`)가 정확히 계산되는지 확인
- [ ] 최고가/최저가 배지가 올바르게 표시되는지 확인
- [ ] 가격 차이 배지 색상: 높음(빨강), 낮음(파랑)

---

## 3. UI/UX 검증

### 3.1 정렬 및 필터
- [ ] 정렬 모드 변경 시 항목 순서가 올바르게 변경되는지 확인
  - [ ] 인기순 (기본값)
  - [ ] 가격 내림차순
  - [ ] 가격 차이순
  - [ ] 이름순
- [ ] 검색 기능: 항목명 또는 코드로 검색 시 필터링 동작 확인
- [ ] 검색 결과가 즉시 반영되는지 확인

### 3.2 페이징
- [ ] 초기 표시: 상위 30개 항목
- [ ] "더 보기" 버튼 클릭 시 추가 30개 항목 로드
- [ ] 남은 항목 수가 정확히 표시되는지 확인

### 3.3 메타데이터 표시
- [ ] 단위(`회/일/건`)가 각 항목에 올바르게 표시되는지 확인
- [ ] 적용 기간(`startDate ~ endDate`)이 표시되는지 확인 (있는 경우)
- [ ] 상세 URL 링크가 표시되는지 확인 (있는 경우)

### 3.4 모바일 뷰
- [ ] 모바일에서 스와이프 비교 뷰가 정상 작동하는지 확인
- [ ] 병원 선택 인디케이터가 정확히 표시되는지 확인
- [ ] 항목 카드가 터치하기 쉬운 크기인지 확인 (48px 이상)

## 4. 성능 검증

### 4.1 렌더링 성능
- [ ] 비교 테이블 렌더링 시간 < 1초 (데스크톱)
- [ ] 비교 테이블 렌더링 시간 < 3초 (모바일)
- [ ] React Profiler로 메모리 누수 확인 (없어야 함)

### 4.2 캐싱 동작
- [ ] 동일 병원 재선택 시 네트워크 재호출 없이 캐시 사용
- [ ] React Query 캐시 TTL 12시간 확인
- [ ] 백엔드 캐시 TTL 12시간 확인

### 4.3 네트워크 최적화
- [ ] 병원 3개 선택 시 API 호출이 병렬로 처리되는지 확인
- [ ] 불필요한 재호출이 없는지 확인 (Network 탭 확인)

## 6. 엣지 케이스 검증

### 6.1 빈 데이터
- [ ] 가격 정보가 없는 병원 선택 시 적절한 메시지 표시
- [ ] 항목이 0개인 경우에도 비교 테이블이 정상 렌더링되는지 확인

### 6.2 대용량 데이터
- [ ] 항목이 500개 이상인 병원 선택 시 성능 저하 없이 표시되는지 확인
- [ ] 페이징이 정상 작동하는지 확인

### 6.3 동시 선택
- [ ] 최대 5개 병원 선택 제한이 정상 작동하는지 확인
- [ ] 5개 초과 선택 시도 시 적절한 안내 메시지 표시
